# Semi Design System — UI Rules

All web UI here follows the **Semi Design System** (`@semi/ui`, repo `https://github.com/hoanghuynh296/semi-nextjs-codebase`). `npx semi-lint` enforces most of this; the full rules are `node_modules/@semi/ui/docs/QUICK_REF.md` (details in `docs/DESIGN_SYSTEM.md`).

**Semi 1.0 in short** (`DESIGN_SYSTEM.md` §0): one look for every brand; neutral grey surfaces; **the brand colour only on the one main button of a page or modal (at most one filled brand button per page or modal), the nav's main action, the active big-tab underline, attention badges / "Mới" tags, or a case the app's owner asks for**, every other action a neutral button; headings 400 / 500, never bold; content text 14px (`text-ui`), shell chrome 12px (`text-chrome`), fields 16px on phones. Upgrading from 0.x: `docs/MIGRATION-1.0.md`.

1. **Ask Semi before writing UI.** Find the component for each need with the `semi` MCP tools (`semi_search` → `semi_docs` → `semi_example`; `semi_block` for whole pages; `semi_props` for props) or the terminal (`npx semi search "bảng có sắp xếp"`, `npx semi docs DataTable`, `npx semi example data-table`, `npx semi add dashboard`). They answer from the installed `@semi/ui`. Read *When to use*, *Use something else when* and *Accessibility*, then start from an example.
2. **Compose, never re-create.** Import from `@semi/ui` and `@semi/ui/styles` directly. No local wrappers (`components/ui.tsx`), no raw `<select>`, `<table>`, `<dialog>`, `type="date"`, `type="number"`, `window.confirm` / `alert`, no inline `<svg>` or glyph icons (`<Icon name>`, mapping in `docs/ICONS.md`). Every AI conversation is `AIChat`; agent work uses `Reasoning`, `ToolCall`, `TaskList`, `Terminal`, `Sources`; an outward-facing, paid or irreversible agent action waits for `ActionConfirmation`. Pages sit in `AppShell` (or `AppHeader` for a one-screen tool) with `PageTitle` (or the title on the toolbar row: `SubpageToolbar title`, or `TextTabs` for 2–4 sub-pages; a detail page opens with `MinimalHeader`); the shell's one brand-filled action is `mainAction`, its bottom row is `tools` (+ `toolsMenu`), the account (with the theme) is the route header's avatar menu (`header.account`; the nav has no account), and phones use its drawer; sub-views of one area go in nav `children` (closed until the parent is chosen, optional grey icon, no colour or count; check `useAppShell().submenuVisible` and add a page picker when false); a list page that people search and filter opens with `StickyContextBar` (`SearchPill` with `BarActions` in `trailing` for pinned actions, `FilterChipRow` with `sort` and `selection` on `md+` / `PhoneFilterBar` + `FilterPanel` on phones, no `ResultLine`), filter and sort state in the URL (`useFilterParams`), chips on one line, never wrapped rows (`filter-chip-wrap`, warning); dialogs are `Modal` / `Drawer` / `confirmDialog`; loading is `Skeleton`, never "Đang tải…" text, and a list, grid or table never swaps its rows for a `Spinner` (`no-spinner-in-list`, warning). `AppShell` renders once in a `layout.tsx` (never from a page), its items route by `href` (not `onSelect` + `router.push`), the session check runs once in that layout (best on the server) with `BootLoader` as the only centred spinner, and content loading is a `loading.tsx` with `PageSkeleton` inside the shell, never a skeleton gate around it. No other UI or icon library (`lucide-react`, `react-icons`, `@radix-ui`, `@mui`, a shadcn `components/ui` copy: `foreign-ui`), no own `Card` / `Badge` / `Tooltip`… (`local-primitive`), no raw `<button>`, `<input>`, `<textarea>`, `<table>` (`raw-control`), no hand-made overlay or spinner (`custom-overlay`, `custom-spinner`); a clickable card is `<Card onClick>` (keyboard-ready), never `<div onClick>` (`click-target`).
3. **Tokens only** (dual theme, any brand):
   - Colour (`docs/TOKENS.md`): surfaces `bg-canvas|app|panel|field|raised` (+ `bg-card` for a card in content, never `bg-panel`; `bg-panel-0…4`); text `text-strong|body|muted|faint` (faint only for group labels, kbd hints, "Untitled", on page surfaces and cards); lines `border-line|divider`, `border-control-line` (checkbox, radio), `border-field-line` / `border-outline-line`; neutral states `bg-item-hover` (hover), `bg-item-selected` (open record, active item, selected option), `bg-item-checked` (checked rows), `bg-inverted text-on-inverted` (checked controls), `ring-focus` / `border-focus` (focus); status `bg-*-bg border-*-border text-*-fg` (danger, success, warning, info) and tones `text-tone-*` only on tags, tiles and dots. Pages separate by tone, not borders or shadows (`<Card bordered>` only for a dense data view). **Brand fills** `bg-primary hover:bg-primary-hover text-on-primary` (and `bg-secondary` … when the brand has one) only where the brand colour rule says; selection, links, check marks, active tabs and focus are neutral. Never physical colours (`bg-white`, `text-slate-900`, `text-amber-600 dark:text-amber-400`), arbitrary colours (`bg-[#…]`), `accent-*` or `primary-50…900` (removed in 1.0), gradients or glow shadows.
   - Buttons (`DESIGN_SYSTEM.md` §0, §9): ordinary actions are neutral. `Button` is `subtle` by default; `surface` for toolbar actions; `inverse` for the main action of a card or a list title row (`size="xs" shape="round"` for the pill), `outline` beside it; `ghost` for icon buttons; `primary` / `secondary` (the brand fills; `secondary` is the brand secondary, the primary when the brand has none) only for the one main button of a page or modal (its commit action), the nav's `mainAction` or a case the app's owner asks for; `danger` for destructive. Attention counts are `CountBadge` / Button `badge`, a new item is `NewTag`. Tabs (`DESIGN_SYSTEM.md` §0, §4h): `PillTabs` for 5+ sections or sections with icons (settings-like pages), `SegmentedControl` for 2–5 filter values shown in full with counts (replaces deprecated `Pills`), big `TextTabs` for 2–4 top-level views of a discovery or reading page (display face at 400, brand underline), `FilterChipRow` for filters, `Tabs` for sections of one record, `useTabParam` for `?tab=` URL state without history spam per arrow key.
   - Layouts (`DESIGN_SYSTEM.md` §4a, `Page`, `SubNav`, `ListReaderLayout`, `ReaderHeader`): **work** pages (lists, tables, workspaces) flush with no centred max-width (padding 16 / 24); **reading** pages (settings, explore, articles) one column centred at 1536px inside 16px padding + 64px bottom; **two-column** pages a 240px `SubNav` card + 4px gap + main card (padding 24, stacking below `md`); **list + reader** a list card + reader card (`ListReaderLayout` on `Page fixed` / `AppShell page="fixed"`, sticky `ReaderHeader` with wrapping title left and `[•••]` + one main action right). Rhythm 32 / 28 / 32 / 16 / 8 (`PageSection`, `PageGrid`). A work page's `PageTitle` is 18 / 400 on the row of its main action (`variant="reading"` 44 / 500 display on reading pages only); one `h1` per page. List pages omit `ResultLine` (16px under filter row), put sort + "Chọn" on `FilterChipRow` / `PhoneFilterBar`, and swap bulk actions in place on the filter row at the same height (`useListSelection`).
   - Type scale only (`docs/TOKENS.md`): `text-ui` (14, content: rows, labels, fields, buttons, body) · `text-chrome` (12, shell chrome only: nav, breadcrumb, toolbar, meta) · `text-lead` 15 · `text-figure` 18 · `text-section` 20 · `text-tab-xl` · `text-title-xl` · `text-hero` · `text-tag` / `text-badge` 10 · `text-overline` · `max-sm:text-input` 16 for fields; text colours `text-strong|body|muted|faint`; headings not bold (400 / 500, `font-title` 500; 600 only overlines, 700 only count badges), titles and big numbers `font-title` / `font-figure`; `tabular-nums` for numbers; sentence case (the one uppercase style is `text-overline`, only as a group or section label: a nav / drawer group, a palette group, a mega menu column, a section of a form or detail panel; never one field's label, a button, a link or a heading: `overline-place`). Content (list rows, table cells, field labels and help, buttons, menu items, sentences) is `text-ui` (14); only the shell chrome (nav, breadcrumb, toolbar compact buttons) and meta (a time, a count, a hint) are `text-chrome` (12). Each size sets its own line height: no `leading-*` on body text.
   - Spacing by role (scaled by density): `p-card` inside every card, popover and panel section (`<Card>` sets it; `p-card sm:p-panel` for a roomy one), `gap-stack` between items in a card or form, `gap-group` between cards, `gap-section` between page sections. `gap-1`–`gap-2`, `px-2`, `py-1` only inside one control or row. A card is never tighter than `p-card` (`card-padding`). No arbitrary spacing, z-index or opacity (`p-[13px]`, `z-[9999]`, `bg-panel/[0.05]`: `arbitrary-value`); no `shadow-sm…2xl` (`tw-shadow`), `uppercase` (`text-case`) or `leading-*` other than `leading-tight` (`leading-override`); no colours, sizes or radii in `style={{}}` (`inline-style-value`) or in `.css` (`css-raw-value`).
   - Shape and size are Semi's one look (no styles since 1.0; a leftover `data-style` does nothing): `rounded-chip|control|card|panel|full`, `shadow-card`, `h-control`, `h-field`. Never `rounded-lg`, `rounded-[Npx]`, `h-[34px]` or `[data-style]` selectors. Density and type scale are this product's (`data-density`, `data-type-scale`): never tune paddings or text sizes by hand for that.
   - Layers: `z-sticky` < `z-drawer` < `z-modal` < `z-dialog` < `z-popover` < `z-toast` < `z-tooltip`; never `z-[9999]`.
4. **Not the generic AI screen** (`DESIGN_SYSTEM.md` §19): one main block per screen (`KpiCard featured`, not four equal cards); icons neutral unless they mean a status; proof (a real number, a quote, a product shot) instead of three icon feature cards; icons only where they help scanning; sample data and empty states from this product, never "Lorem", "John Doe" or another domain.
   **Density budgets** (`DESIGN_SYSTEM.md` §4c, measured on the page by `npx semi density <url>`): at most three frames inside each other (page panel › card › tile); at most four text sizes and three colours (brand + status) in one box; one filled brand button per page or modal; text 12px from a box's sides and 8px from its top and bottom; a list row at least `h-control` tall (`Item`, `Menu`, `DataTable`); 8px or more between boxes; one line between two things (no `border-b` on a card's last row). `px-2` / `py-1` are for the inside of a control, never a row's or a box's padding.
   **Every state** (`DESIGN_SYSTEM.md` §19b, §13c): use `EmptyState` (`first-use` / `no-results`), `ErrorState`, `NotFound`, `Forbidden`, and give each route group `loading.tsx` / `error.tsx` / `not-found.tsx` (`npx semi example states`); each screen has its loading (skeleton of the real shape), empty (with the action that fills it), "no result", error (what failed + retry, loaded data kept), no-permission and too-much-data states; a destructive action is undoable (`toast.undo`) or, when irreversible, confirmed (`confirmDelete`); Escape closes, Enter submits, back works.
   **Feedback** (`DESIGN_SYSTEM.md` §14c): one toast API from `@semi/ui` (`toast.success|error|warning|info`, `toast.undo`, `toast.promise`), never a toast library or a local wrapper (`local-toast`, warning); a reversible destructive action is done at once with `toast.undo(title, restore)` (Hoàn tác, 8 s); an irreversible one asks first with `confirmDelete({ name })` (names the object, red Xoá, Huỷ); success is one toast, never a modal (`npx semi example toast`).
   **Grouped actions** (`DESIGN_SYSTEM.md` §9, G1–G12): one way to start one job (other ways to create the same thing go under the primary in a `SplitButton`, never as extra toolbar buttons); secondary page actions in the ⋯ `Menu` (at most one secondary button visible); `ButtonGroup` only for toggles or steps of one control; a table row has one inline action + ⋯, a card `CardActions` (always with `label`: `card-hover-actions-touch` is a hard error); a round icon button is `<Button iconOnly shape="round">`, never a hand-made `rounded-full` button (`raw-pill-button`, warning); danger last; one filled primary per view; 3+ icon-only buttons in a row go into ⋯. A list record opens in a `DetailOverlay` with `useDetailParam` (`?open=`), not a new page (`detail-overlay-url`, warning); the ⌘K box is one `CommandPalette` in the root layout (pages add items with `useRegisterCommands`).
   **Forms** (`DESIGN_SYSTEM.md` §9b): the action row is `FormActions` (Huỷ ghost, then Lưu / Tạo, destructive on the left, sticky on a page); `useUnsavedGuard(dirty)` so typed work is never lost; `Field kind` for email / phone / number / money / URL / search / password; errors under the field (`useFormValidation`, `FormErrorSummary`), never in a toast; page forms `max-w-2xl` (`npx semi example form-actions`).
5. **Brand** (when `semi-lint.json` has `"brand"`): ask `semi_brand` (or `npx semi brand voice|color|logo|brief`) before writing UI text or placing colour. Write in the brand's voice, use its fills only as the brand colour rule says, import the logo from the kit; never define colours, fonts or Semi tokens in the app (`brand-override`). Brand changes happen in the brand repo with `/semi-brand`, then `/semi-sync` here.
6. **Accessibility** (`DESIGN_SYSTEM.md` §18, checked on the page by `npx semi a11y <url>`): icon-only controls have `aria-label`, and a field's name comes from `Field` (a placeholder is not a label); anything clickable is a button or a link (`click-target`); custom controls keep `FOCUS_RING` or the 2px `:focus-visible` `outline-focus`, never a bare `outline-none` (`focus-hidden`); every text / background pair reaches 4.5:1 in both themes (themed text tokens, never a fixed shade on a tinted surface); text-like fields use the quiet 1.0 style (`border-field-line`, backed by the 2px `:focus-visible` outline), checkboxes and radios keep `border-control-line` (3:1); a control drawn smaller than 24px gets `HIT_AREA`; images have `alt`; never `maximum-scale` or `user-scalable=no` in the viewport.
7. **Gaps go upstream, lint is never silenced.** When `@semi/ui` cannot express a need, run `/semi-sync`, re-check the docs, then `/semi-propose`; meanwhile a minimal compliant workaround marked `// TODO(semi#<issue>)`. Never add a `skip`, disable a rule or grow `semi-lint-baseline.json` to get past lint: fix the code. The baseline only shrinks (`semi-lint --update-baseline`); `--accept-new` is for `/semi-sync` and needs the user's OK otherwise, and `semi-lint --ci` fails a pull request whose baseline or skips grew. The one per-file `skip`, with the user's OK and a reason, is for illustrations and data colours (not UI chrome): `"skip": { "literal-colour-value": { "lib/scenePalette.ts": "data colours: 3D scene" } }` (also `inline-svg-path`, `no-literal-palette`, `inline-style-value`). Shared rules change in the Semi repo, never only in this file; app-specific patterns go in `docs/UI_EXTENSIONS.md`.
8. **Before finishing:** `npx semi-lint` clean (it also checks `.css`), `npx tsc --noEmit`, the page checked in both themes and at phone width, and `npx semi density <url>` and `npx semi a11y <url>` clean when the app runs (no Playwright: evaluate their `--snippet` with a browser tool, `a11y` in each theme). CI runs `semi-lint --ci` and `tsc` (`.github/workflows/semi.yml`). Whole-app check: `/semi-check`; newer Semi or brand kit: `/semi-sync`.
