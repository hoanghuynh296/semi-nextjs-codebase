# Empty state

What an empty list or page shows. `first-use`: one icon, one sentence, the one primary action that fills it. `no-results`: a search or filter matched nothing, with its own title and a “Xoá lọc” action.

## When to use

- First use: no items yet, a feature not set up (variant first-use).
- A search or filter matched nothing (variant no-results, with onClearFilters).

## Use something else when

| Need | Use |
|---|---|
| The page or the data failed to load | ErrorState |
| A wrong URL or a page the user cannot open | NotFound / Forbidden |
| Data is still loading | Skeleton in the shape of the content |

## Import

```tsx
import { EmptyState } from "@semi/ui";
```

## Examples

### Plain

```tsx
import { Button, EmptyState } from "@semi/ui";

export default function EmptyStateBasic() {
  return (
    <EmptyState
      icon="printer"
      title="Chưa có máy in nào"
      description="Thêm máy in đầu tiên để theo dõi tiến độ và nhiệt độ."
      action={
        <Button variant="primary" icon="plus">
          Thêm máy in
        </Button>
      }
    />
  );
}
```

### First use

One icon, one sentence, one primary action.

```tsx
import { Button, EmptyState } from "@semi/ui";

export default function EmptyStateFirstUse() {
  return (
    <EmptyState
      variant="first-use"
      icon="printer"
      title="Chưa có máy in nào"
      action={
        <Button variant="primary" icon="plus">
          Thêm máy in
        </Button>
      }
    />
  );
}
```

### No results

A filter matched nothing: different title, “Xoá lọc” clears it.

```tsx
import { EmptyState } from "@semi/ui";

export default function EmptyStateNoResults() {
  return <EmptyState variant="no-results" title="Không có máy in khớp bộ lọc" onClearFilters={() => {}} />;
}
```

## API

### EmptyState

Empty list / first-run state (docs/DESIGN_SYSTEM.md §13).
- `first-use`: nothing exists yet. One icon, one sentence (the title), one primary action (`action`).
- `no-results`: a search or filter matched nothing. Own title, and `onClearFilters` adds a "Xoá lọc" button.
Below `sm` it takes at most 40% of the viewport (compact padding, scrolls inside if a long text still overflows).

| Prop | Type | Default | Description |
|---|---|---|---|
| `icon` | `IconName` |  | Defaults: `search` for no-results, `box` otherwise. |
| `title` | `React.ReactNode` |  | Defaults: "Không có kết quả" for no-results, "Chưa có dữ liệu" otherwise. |
| `description` | `React.ReactNode` |  | One short hint. A `first-use` state needs none: the title is its one sentence. |
| `action` | `React.ReactNode` |  | The one primary action (a filled Button) that fills the list. Not used by `no-results` when `onClearFilters` is set. |
| `variant` | `'first-use' \| 'no-results'` |  | `first-use` (nothing yet, one primary action) or `no-results` (a search / filter matched nothing). Omit for the plain state. |
| `onClearFilters` | `() => void` |  | no-results: clears the search and filters; renders a secondary "Xoá lọc" button. |
| `className` | `string` |  |  |

## Accessibility

- The action is a normal button; below sm the state takes at most 40% of the viewport.

## Notes

- When the list is empty and the state shows its own primary action, hide the primary button in the page's title row (one filled button per view, §13).
- Keep the title and toolbar on screen around a no-results state: the user must be able to change the filter.
