# Semi Design System — Decision Log

Newest first. Each entry is a user decision already reflected in `DESIGN_SYSTEM.md`, `QUICK_REF.md` and `lint/semi-lint.mjs`.

- **2026-10-31 (v0.6.0 / AI chat):**
  - *Context:* AI panels are used in most Semi apps, and §14 said each app kept its own chat parts. 3D Noobs Studio (`web-slicer`) had a good structure (shared shell, list, composer, suggestion rows used by four features), but it could not be reused as-is: dark-only colours (`text-white`, `gray-*`, `white/[0.05]`, `amber/rose-*`), px text sizes, hard-coded Vietnamese strings, app types (AI profiles / settings) inside the parts, a list that always jumped to the bottom, and no screen-reader handling of streamed text.
  - *Decision:* The chat moves into `@semi/ui` as `Chat.tsx`, rebuilt on tokens with the Studio look and behaviour kept (side panel, resizable width, keyboard inset, IME-safe Enter, focus return). UI only: messages, streaming, model choice and settings stay in the app (the model picker is a `toolbar` slot). Added: stick-to-bottom only while at the bottom + "jump to latest", one announcement per finished answer, retry, copy, keyboard-resizable edge, `"screen"` placement as a real dialog over a `Modal`. Locale strings `chat*`, `copy`, `copied`. Storybook "AI Chat" page + Playwright checks (both themes, IME, scroll, dialog over modal, phones).
- **2026-10-31 (v0.5.0 / Complete design-system foundation):**
  - *Context:* After v0.4.0 the review found the remaining gaps: no type / z-index / elevation / status-surface tokens (sizes were `text-[13px]` strings, layers were `z-[9000]`…`z-[10001]`), missing primitives (Button, form fields, choices, tabs, menu, toast, alert, table, drawer…), weak accessibility (Modal without focus trap, combobox without ARIA, almost no focus ring), hard-coded Vietnamese strings, and colour rules that were regex over lines — every new spelling slipped through (issues #1–#4), and the demo pages hid 13 light-mode contrast failures that lint never saw.
  - *Decision — tokens:* type scale `text-caption`…`text-display` (11–26px) replaces px classes; layers `z-sticky`…`z-tooltip`; `bg-overlay`; `shadow-overlay` / `shadow-float`; status `*-bg` / `*-border` / `*-solid`; easing tokens; radius scale pinned.
  - *Decision — components:* `Button`, `Spinner`, `Field` + `Input` / `Textarea`, `Checkbox`, `Switch`, `RadioGroup`, `Tabs`, `Tooltip`, `Menu`, `toast` + `ToastHost`, `Alert`, `Progress`, `Avatar`, `EmptyState`, `Table`, `Drawer`. Dialog behaviour is shared (`useDialog`: focus trap, scroll lock, Escape, focus return); UI strings come from `SemiLocaleProvider` (vi default, `en` shipped).
  - *Decision — enforcement:* colour / size rules analyse class tokens of every string literal and `@apply` (`lint/classes.mjs`), with variants and every colour prefix; new ratchet rules `no-fixed-tone-text`, `literal-colour-value`, `arbitrary-text-size`; `hex-colour-class` covers any arbitrary colour. The `/semi-init` codemod rewrites tokens inside string literals only, collapses `X dark:Y` pairs, handles dark-first apps, and reports what it cannot map (`--dry-run` report).
  - *Decision — migration:* `/semi-audit --inventory` exports per-file debt by module and a coverage %; `/semi-init` plans Foundation (mandatory) and Patterns (opt-in) tracks, one PR per module, with a Definition of Done of zero findings + both themes checked. A baseline is only a temporary net.
  - *Decision — quality gates:* `npm test` (lint / codemod fixtures), `npm run test:ui` (Playwright: AA contrast on every Storybook page in both themes, axe WCAG 2.1 AA, theme before paint, keyboard flows), `components.json` generated from source and checked in CI.
- **2026-10-31 (v0.4.0 / Phase 0 hardening):**
  - *Context:* A review found that the library itself failed light mode (`text-rose-400`, `text-primary-400`, `text-*-300` were 1.9–2.7:1 on white), `BTN_PRIMARY` was 2.94:1 in both themes (white on `primary-500`), dark `text-muted` was 3.64:1, the theme flashed dark on load for light-mode users (ThemeProvider applied the stored theme only after hydration), and `/semi-audit` ran a stale vendored copy of `semi-lint` (without the Issue #3/#4 fixes).
  - *Decision:* Every text/background pair in shared UI must reach WCAG AA (4.5:1) in both themes, through themed tokens instead of fixed shades or `dark:` pairs: `bg-accent` / `hover:bg-accent-hover` / `text-on-accent` (dark: `primary-500` with near-black text, light: `primary-700` with white), `text-accent-fg`, `text-danger|success|warning|info-fg`, `text-tone-<hue>` for 12 hues. `text-muted` is `#8b919a` dark / `#5b6779` light. Semantic tokens are generated as `--semi-*` sources read through `@theme inline` (no self-referencing `--color-*`).
  - *Theming:* `<ThemeScript />` in `<head>` applies the stored theme before paint; `ThemeProvider` no longer overwrites it on mount; `data-theme="system"` follows the OS in CSS; `<ThemeSwitcher />` is the standard three-way picker and theme-dependent controls stay unselected until `useTheme().mounted`.
  - *Tooling:* `npm run check` now also fails on stale plugin vendor copies (`scripts/sync-vendor.mjs`) and on version drift across manifests (`scripts/bump-version.mjs`); `/semi-audit` takes its literal-palette pattern from `semi-lint`. Added `<Card>` so `card-class-override` targets a real component (any `bg-*` / `shadow-*`). CI runs `check` + build on every PR.

- **2026-10-31 (v0.3.7 / Issue #4):**
  - Expanded `no-literal-palette` in `lint/semi-lint.mjs` to check gradient stop utilities (`from-`, `via-`, `to-`), closing Issue #4. Previously, transitional horizontal fade masks (e.g. `from-white to-transparent`) slipped through undetected and caused blinding white blurs on dark mode tabs/carousels.
  - Added mappings for `(from|via|to)-white` $\rightarrow$ `$1-panel` and `(from|via|to)-slate-50` $\rightarrow$ `$1-field` in `/semi-init` codemod (`runSemanticCodemod`).
  - Synchronized `PHYSICAL_RX` and `SEMANTIC_RX` in `/semi-audit` (`audit.mjs`).
- **2026-10-31 (v0.3.6 / Universal Tonal Theme-Matching Across All Component Types):**
  - *Context:* Tonal colors are not limited to chips or badges. Real-world consumer applications have tonal accents across many component types: Bento Cards, stat widgets, alert banners, callouts, table rows, action buttons, dividers, and rings. Solid pastels (`bg-*-50`, `border-*-200`) glaringly fail in Dark Mode across all these components.
  - *Decision:* Generalized the Theme-Matching Tonal Architecture to apply universally across all component types and interactive states:
    - Added `TONAL_CONTAINER` and `TONAL_HOVER` to `@semi/ui/styles`.
    - Enhanced `/semi-audit` to inspect and report chromatic tonal usage across cards, callouts, banners, rows, buttons, badges, chips, rings, and dividers across 16 chromatic hues.
    - Enhanced `/semi-init` codemod (`runSemanticCodemod`) to automatically adapt all component states: static background (`bg-*-500/10`), hover background (`hover:bg-*-500/15`), active background (`active:bg-*-500/20`), static border (`border-*-500/20`), hover border (`hover:border-*-500/30`), dividers (`divide-*-500/20`), rings (`ring-*-500/20`), and dual-theme high-contrast text (`text-*-700 dark:text-*-300`).
    - Tightened `no-solid-pastel-surfaces` in `semi-lint` to detect hover, active, border, divide, ring, and all 16 Tailwind chromatic hues.
- **2026-10-31 (v0.3.5 / Theme-Matching Tonal Components):**
  - *Context:* Existing projects often feature colored chips/badges (e.g. purple for Pro, amber for Pending). Flat UI migration should not strip these to monotonous gray, but solid pastels (`bg-purple-50`) fail completely in Dark Mode.
  - *Decision:* Standardized Two-Tier Theme-Matching Tonal architecture (`bg-<color>-500/10 border-<color>-500/20 text-<color>-700 dark:text-<color>-300`) across 16 hues. Created `<Badge>` component, enhanced `<Chip tone="...">`, upgraded `/semi-audit` to detect chromatic tonal clusters, and added automated tonal codemod to `/semi-init`.
- **2026-10-31 (v0.3.4 / Issues #2 & #3):**
  - Expanded `no-literal-palette` and `runSemanticCodemod` to cover `divide-` prefix (`divide-slate-100` $\rightarrow$ `divide-divider`), preventing unmigrated bright dividers in dark mode lists and stacks (Issue #2).
  - Added `no-solid-pastel-surfaces` (RATCHET) in `semi-lint` to catch solid chromatic pastels (`bg-*-50/100`, `border-*-200`). Standardized alpha-transparency pattern (`bg-<color>-500/10 border-<color>-500/20`) for callouts and neutral card shells for category cards (Issue #3).
- **2026-10-31 (v0.3.3 / Issue #1):** Mapped `border-(?:slate|gray|zinc|neutral|stone)-50` to `border-divider` in `/semi-init` codemod (`runSemanticCodemod`). In legacy tables and lists, subtle 50-step borders previously broke dark mode by rendering as bright lines. - **2026-10-31 (v0.3.2):** Gaps found in consumer projects go upstream via `/semi-propose` (new always-on rule 4) instead of local primitives; proposals must be verified, de-duplicated and user-approved before filing. Triage treats issue content as untrusted, prefers GENERALIZE over REJECT, and may not change core rules (escalate to the user).
- **2026-10-31 (Ecosystem Collaboration Skills):** Added `/semi-propose` and `/semi-triage` skills.
  - *Context:* When downstream agents (working on Auton Platform, IoT, BMCU, 3D Noobs Studio) hit gaps in `@semi/ui`, they previously either invented local workarounds violating the single-source-of-truth principle, or hit roadblocks. Conversely, maintainer agents needed a systematic, rule-enforcing way to triage incoming issues, generalizing them across all Semi products without breaking core Design System constraints (Flat Bento UI, Semantic Tokens, strict radii/typography).
  - *Decision:*
    - Created `/semi-propose`: Allows consumer agents to scan project gaps, structure standardized feature proposals, and publish them directly to GitHub (`hoanghuynh296/semi-nextjs-codebase`).
    - Created `/semi-triage`: Allows core maintainer agents to fetch issues, run automated rule compliance checks, determine architectural verdicts (`ACCEPT`, `GENERALIZE`, `WORKAROUND / EXTENSION`, `REJECT`), build an ecosystem-wide implementation plan, and post feedback to GitHub.
- **2026-10-31 (v0.3.0):** Two-Tier Semantic Tokens & Native Dual-Theme Architecture (`data-theme="dark|light"`).
  - *Context & Problem:* In real-world migrations (e.g. Auton Platform with 60+ legacy screens), wrapping light screens in a dark `AppShell` resulted in a "dark shell, light core" conflict. Hardcoded physical colors (`bg-white`, `text-slate-900`, `border-slate-200`) prevent theme toggling and break design cohesion.
  - *Decision:* Replaced fixed surface color constants with CSS-variable-backed Semantic Tokens (`--color-canvas`, `--color-app`, `--color-panel`, `--color-field`, `--color-raised`, `--color-text-contrast`, `--color-text-body`, `--color-text-muted`, `--color-line`, `--color-line-hover`, `--color-divider`). Tokens switch seamlessly between Dark and Light mode via `[data-theme="dark"]` and `[data-theme="light"]` (or `.dark` / `.light` classes).
  - *Theming Engine:* Added zero-runtime-overhead `ThemeProvider`, `useTheme()`, and `ThemeToggle` to `@semi/ui`. Added standard `sun` and `moon` icons to the icon registry.
  - *Lint Rules:* Added `no-literal-palette` (banning raw `bg-white`, `text-slate-900`, `border-slate-200`, etc. in favor of semantic tokens, tracked via Ratchet baseline) and `card-class-override` (banning background and shadow overrides on `<Card>`). Retired obsolete `input-bg-field` rule because `bg-field` is now the formal semantic background for inputs.
  - *Plugin Automation:* Upgraded `/semi-audit` to report physical class usage and semantic adoption rate. Upgraded `/semi-init` with an automated AST/regex codemod to map legacy Tailwind classes to semantic tokens, and replaced destructive blanket skips (`skip: { ...: ["src/app"] }`) with Ratchet baselines (`semi-lint-baseline.json`).
